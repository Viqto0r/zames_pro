# BACKLOG — что улучшить в zames

Анализ по состоянию на коммит `d58f019` (версия 2.49.3). Рабочий список идей, не обязательство к исполнению. Порядок внутри разделов — от более важного к менее важному.

## 1. Архитектура и размер модулей

Главная структурная проблема — несколько файлов разрослись настолько, что их тяжело читать и менять точечно.

- `src/index.ts` — ~3694 строки. CLI, главный цикл, диспетчер слэш-команд, очередь сообщений, `/goal`, `/loop`, тикер шедулера, подмена `console.log/console.error`, работа с сессиями. Разбить: `cli.ts` (аргументы/help), `main-loop.ts` (main + takeInput + очередь), `slash.ts` (диспетчер команд), оставив `index.ts` тонким входом.
- `src/browser.ts` — ~3335 строк. Фасад над Playwright, логин, вложения, чтение истории, сети-хук, детекторы обрыва генерации, throttling. Часть уже вынесена в `net-capture.ts`; дальше вынести `auth.ts`, `history.ts`, `attachments-upload.ts`, `generation-watch.ts`.
- `src/input.ts` — ~1824 строки: и `LineEditor`, и чистые хелперы (layout, visLen, charWidth, token-status, paste). Вынести чистое в `input-layout.ts`.
- `src/agent-loop.ts` — ~1702 строки: сам цикл, парсинг tool-call, сторожа/ретраи, auto-compact. Вынести парсинг вызова и сторожа в отдельные модули.
- `src/i18n.ts` — ~1341 строка одного `CATALOG`. Разбить по доменам (spinner, config, help, commands, agent) и собирать в один объект.
- `src/commands.ts` — ~863 строки чистых хелперов команд. Кандидат на разделение по командам.

## 2. Локализация: утечки русского мимо i18n

По AGENTS.md всё, что видит ОПЕРАТОР, должно идти через `CATALOG` из `src/i18n.ts`. Сейчас есть захардкоженные русские строки, которые не переведёт `/config lang en`:

- `src/browser.ts` — `console.error('profile: …')`, `'auth: …'` (несколько мест). Должны уходить через `browser.onNotice` / `ui.warning()` и ключи i18n, а не в stderr.
- `src/config.ts` — `config: не удалось прочитать <file>` (и `throw new Error` с русским текстом).
- `src/self-review.ts` — множество `console.log` с русскими строками (снапшоты, отчёты, `/self-*`).
- `src/transcript.ts` — `transcript: ошибка записи`.

Плюс: часть сообщений идёт напрямую в `console.error`, что при активном `LineEditor` перезатирается его статус-строкой (та же проблема, что чинили для `browser._notice`). Ввести единый `notice()` и запретить прямой stderr в этих модулях.

## 3. Тесты

- Многие тесты лезут в приватные поля/методы через `as unknown as { _handle: … }`, `_eraseInputOnly` и т.п. Это хрупко: переименование ломает тесты, а поведение проверяется не через публичный контракт. Постепенно заменить на публичные хуки/инъекцию зависимостей (например, рендер-«терминал» как отдельный класс).
- Нет измерения покрытия. Добавить `c8`/`node --experimental-test-coverage` в CI и не давать покрытию падать.
- Тесты завязаны на тайминги (`setTimeout`, `unref`-таймеры, комментарий в CI про Node 22). Флаки-риск. Помогает внедрение fake timers (`node:test` mock timers).
- В выводе листинга `test/large-call.test.ts` фигурирует дважды — проверить, нет ли дубля имени.

## 4. CI и релиз

- CI (`.github/workflows/tests.yml`) жёстко на Node 24, потому что на Node 22 раннер отменяет тесты с `unref`-таймерами. При этом `engines` в package.json — `node >=18`. Рассинхрон: заявлена поддержка 18+, фактически проверяется только 24. Либо поднять `engines` до `>=20`/`>=22` и добавить матрицу, либо починить тесты под старые Node.
- Нет `packageManager` (corepack) — версия npm/Node не зафиксирована.
- Нет `CHANGELOG.md`. Есть коммиты `chore: release X.Y.Z`, но история версий не собирается автоматически. Добавить генерацию changelog или ручной файл.
- `src/mcp.ts` рекламирует версию `'1.0.0'` строкой — расходится с package.json. Читать версию из package.json.
- Хук `pre-commit` гоняет `typecheck && test`, `pre-push` — `format:check && test && build`, но `lint` есть только в CI. Добавить `lint` в хуки для локальной согласованности.

## 5. Конфиг

- `PROJECT_CONFIG` вычисляется на уровне модуля через `process.cwd()`. После `/cd <path>` (и вообще смены рабочей директории) проектный `.zamesrc.json` не перечитывается — путь зафиксирован на момент импорта. Пересчитывать путь при смене workdir или читать конфиг лениво.
- `writeConfigValue` пишет только в домашний конфиг (осознанно), но стоит явно задокументировать, что проектный конфиг — только для чтения.
- Часть «горячих» значений применяется к рантайму (`ui.locale`, `ui.contextLimit`, `browser.deepThinking/webSearch`), но не все. Ревизовать `CONFIG_SCHEMA` и пометить, какие ключи требуют рестарта, а какие — нет.
- Часть таймаутов в `DEFAULTS`, но часть захардкожена в `browser.ts` (интервалы ожиданий, стабильность, gap для Continue). Вынести в конфиг или именованные константы.

## 6. Обработка ошибок

- Почти нет собственных классов ошибок (`extends Error` ~2). Различение режимов сбоя идёт по строковому сопоставлению SSE/DOM (`isGenerationIncompleteText`, `isFinishedWithoutAnswer`, `looksLike*`). Хрупко и жёстко связывает код с текстами DeepSeek. Ввести типизированные ошибки (`GenerationIncompleteError` уже есть — расширить подход), а строковые детекторы держать в одном модуле с фикстурами.
- Много пустых `catch {}` (attachments, browser, compact, index, input, net-capture, self-review, sessions, transcript, undo, web, xml-toolcall). Часть оправдана (best-effort), но стоит логировать в debug-режиме или явно комментировать «почему можно глотать».
- `loadConfig` при битом JSON пишет в `console.error` (см. п.2) и продолжает — ок, но сообщение пользователю должно идти через UI.

## 7. Работа с файловой системой

- Широкое использование синхронного `readFileSync/writeFileSync/existsSync`. Для CLI приемлемо, но на горячих путях стоит перейти на асинхронные вызовы, чтобы не блокировать event loop во время операций с браузером.
- Атомарность записи: сессии/транскрипт/undo пишутся напрямую. При падении процесса возможен обрезанный JSON. Писать во временный файл и переименовывать (`fs.rename`) для сессий и конфига.
- Нет версионирования формата файлов сессий/снапшотов. При смене схемы старые файлы не мигрируются — добавить поле `version` и мягкую миграцию.

## 8. Безопасность

- Креды DeepSeek (`browser.auth.username/password`) хранятся в открытом виде в `~/.zames/config.json`. Как минимум — предупреждать в `/doctor` и в доке; в идеале — поддержать переменные окружения и не писать пароль на диск по умолчанию.
- `confirmation.alwaysConfirm` — regex по строке команды. Убедиться, что паттерны применяются к нормализованной команде и покрыты тестами на обход (регистр, лишние пробелы, `&&`).
- Подмена `console.log/console.error` в `index.ts` переопределяет глобальные функции. Любая библиотека, печатающая в консоль, начнёт уходить через `printAbove`. Ограничить область (обёртка-логгер вместо подмены глобалов) или документировать риск.

## 9. Документация

- `AGENTS.md` ~70 КБ — очень длинный. Разбить на `docs/` (браузер, инпут, конфиг, команды) и оставить в корне краткое оглавление.
- Нет `CONTRIBUTING.md`, `SECURITY.md`, шаблонов issue/PR.
- README дополнить разделом «Известные ограничения» (зависимость от вёрстки/SSE DeepSeek, rate limit, headless-UA) и таблицей совместимости Node.
- Явно описать формат tool-call и как расширять инструменты (знание размазано между AGENTS.md и system-prompt.ts).

## 10. Производительность и UX

- Спиннер и статус-строка анимируются таймером; при длинных ответах проверить перерисовку на медленных терминалах (Tabby и т.п.) — часть проблем уже чинили, нужны тесты на «не мигает»/«не дрейфует» (последний добавлен: `test/input-no-drift.test.ts`).
- `/chats` и `fetchChatMessages` тянут всю историю; на длинных чатах стоит пагинация/лимит с явным сообщением.
- Вложения копируются в `<project>/tmp`; для больших файлов — предупреждение о размере и очистка по возрасту.
