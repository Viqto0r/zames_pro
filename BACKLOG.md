# BACKLOG

Задачи по багам и инфраструктуре zames. Обновляется по мере выполнения.

## P0 — баги, ломающие работу

- [ ] **`restart()`/`launch()` пересоздают окно браузера (и убивают чужой)**
  `launch()` всегда зовёт `killStaleChrome()`, а `restart()` = `close()` +
  `launch()`. Внутри `ask()` при ошибке `/closed|crash|Target page|browser/`
  вызывается `restart()` — то есть на любой transient-ошибке окно
  закрывается и открывается заново (оператор видит «открылось новое окно»),
  а `killStaleChrome()` на Windows убивает ВСЕ chrome с `/.zames/profile`,
  включая чужой запущенный агент. Надо: (а) не звать restart на ошибки, где
  достаточно переоткрыть страницу; (б) `killStaleChrome` — только для
  процессов, которые стартовали ДО этого инстанса; (в) при resume не
  пересоздавать контекст.

- [ ] **После resume модель теряет контекст («I don't have the repo»)**
  В логе `zames-2026-09-28T14-48-12`: после `resume_chat` модель ответила
  «I can't do most of what you're asking… I don't have the repo». Значит в
  чат ушёл не тот контекст / system-prompt не был переотправлен, а модель
  получила только огрызок. Проверить порядок при resume: `freshChat=false`,
  `sendSystemPrompt=resendPrompt`. Возможно, надо всегда переотправлять
  system-prompt (или его краткую версию) при первом сообщении в resume-чате.

- [ ] **Зависание после `Messages too frequent. Try again later.`**
  Агент получает тост о лимите и «зависает» (ни ответа, ни ошибки в терминале).
  Надо проверить весь путь: классификация тоста → `RateLimitError` → ожидание
  `rateLimitWaitMs` → повторная отправка. Убедиться, что ошибка доходит до
  оператора, что спиннер не залипает, что Esc прерывает ожидание.
  Проверить `RATE_LIMIT_RE` (не слишком ли узкий/широкий), `_readPageText`,
  finish-loop и start-loop в `_askOnce`, `ask()`.

- [ ] **Моргание терминала (Tabby) при вводе символов**
  В Tabby при каждом вводе символа экран «перерисовывается» и мерцает.
  Причина, вероятно, в том, что `LineEditor._render()` делает полный
  erase+write на каждый символ, а также держит дот-анимацию. Нужно уменьшить
  объём перерисовки: не стирать весь блок, если меняется только строка ввода;
  не перерисовывать статус без изменения; учитывать, что `printAbove` дёргает
  полный ре-рендер. Проверить на широких и узких терминалах, с контекстом и без.

- [ ] **Resume чата открывает новое окно браузера**
  При восстановлении чата открывается новое окно вместо использования
  существующего. Проверить `openChat`/`newChat`, работу с контекстом и
  `--user-data-dir`. Не должно быть второго окна.

- [ ] **Дублирование строки «пауза Nс перед отправкой» в терминале**
  Во время ожидания перед отправкой строка статуса печатается много раз
  подряд (см. приложенный лог): каждая тиковая перерисовка оставляет копию
  строки в буфере/на экране вместо того, чтобы заменить предыдущую.
  Проявляется особенно на широком терминале и с токен-контекстом
  (пример: `208k · 21`). Причина, вероятно, в паре erase+rewrite: `_eraseBlock`
  поднимает курсор/стирает блок, но из-за анимации дотов (каждые 400 мс) и
  обновления паузы (раз в секунду) в терминал попадает несколько полных
  перерисовок, а `ESC[J` не покрывает уже прокрученную область. Нужно:
  (а) не перерисовывать статус, если текст не изменился, кроме дотов;
  (б) не печатать паузу отдельными «кадрами» — обновлять одну строку
  in-place; (в) проверить `visRows`/`cursorRowFromTop` на широких терминалах
  и при `printAbove`. Покрыть тестом.

## P1 — инфраструктура качества

- [x] **ESLint с правилом на мёртвый/недостижимый код**
  Подключён ESLint 9 + typescript-eslint. Так как проект собирается
  TypeScript 7, а typescript-eslint пока не поддерживает TS 7 API,
  линтер запускается через `scripts/eslint-ts6.mjs` — он на время процесса
  подменяет модуль `typescript` на `typescript-6` (side-by-side, как советует
  сам typescript-eslint). Включены `no-unreachable`, `no-constant-condition`,
  `no-useless-assignment`, `prefer-const`, `@typescript-eslint/no-unused-vars`.
  Починены все реальные находки. Скрипт: `npm run lint` / `lint:fix`.

- [x] **Prettier + форматирование**
  Подключён Prettier (`.prettierrc`: 2 пробела, single quotes, no semi,
  trailingComma all, printWidth 80), интегрирован с ESLint через
  `eslint-config-prettier`. Весь `src/` и `test/` отформатированы.
  Скрипты: `npm run format` / `format:check`.

- [ ] **CI: lint + format:check**
  Добавить в GitHub Actions шаг с `npm run lint` и `npm run format:check`,
  чтобы новый код соответствовал правилам.
