### Такт 4 (2026-10-17) — исправлено

**Цель:** планировщик `/loop` (жалоба оператора: «задача добавлена», но работа
не началась).

**Баг:** `mergeMessages()` (src/commands.ts) терял `jobId` при склейке
очередных сообщений. Тикер планировщика пропускает задачу, только пока в
`pendingQueue` лежит её копия (`hasQueuedJob`); как только первая копия
снималась из очереди в работу, id исчезал — и тикер снова ставил ту же задачу
на каждом тике, пока первый запуск ещё шёл. Плюс нераспознанный интервал
(`/loop 10min …`) печатал только общую строку usage — выглядело как «добавлено,
но ничего не происходит», оператор повторил задачу руками. Ещё: сразу после
«добавлено» не было сказано, КОГДА она реально стартует (задача не
прерывает текущий ход).

**Фикс:**
- `mergeMessages` сохраняет `jobId` (и одиночное сообщение, и батч);
- при нераспознанном интервале — `sched.interval_typo` (какое значение не
  разобрано, что задача НЕ добавлена, что без единицы — секунды);
- `sched.added_hint` под «добавлено» — когда стартует и как посмотреть/снять.

**Тест:** `test/queue-batch.test.ts` +3 кейса (jobId одиночного/склеенного
сообщения, отсутствие id у операторского батча) — RED до фикса (2 падения),
GREEN после.

**Гейты:** `npm test` 1090 тестов (1080 pass, 0 fail, 10 skip), `typecheck`,

### Такт 5 (2026-10-17) — исправлено

**Цель:** web/SSRF + `WebFetch` (чистая часть `htmlToText`).

**Баг:** `htmlToText()` (src/web.ts) раскодировал числовые HTML-сущности через
голый `String.fromCodePoint(...)`, который БРОСАЕТ `RangeError` на значении
вне Unicode (`&#999999999;`), на суррогате (`&#xD800;`) и на NaN. Исключение
вылетало из `htmlToText` в catch обработчика `WebFetch` — и вся страница
возвращалась как `Error fetching <url>: Invalid code point 999999999`.
Агент терял документ целиком из-за одного битого символа. Второй дефект:
пара суррогатов, записанная двумя ссылками (`&#55357;&#56832;`, т.е. эмодзи),
декодировалась по половинам и оставляла в тексте два lone surrogate.

**Фикс:** `decodeEntityCode()` — недопустимая ссылка отбрасывается (не бросает),
а пара «high + следующий low» склеивается в один астральный символ; состояние
сбрасывается на входе в `htmlToText`, чтобы не утекало между документами.

**Тест:** `test/web-html.test.ts` +3 кейса (вне диапазона, суррогат/пустая
ссылка, склейка пары) — RED до фикса (`RangeError`, «lone high surrogate»),
GREEN после.

**Гейты:** `npm test` 1093 теста (1083 pass, 0 fail, 10 skip), `typecheck`,
`lint`, `format:check`, `build` — зелёные.

**Коммит:** `39a9c0b`.

### Такт 6 (2026-10-17) — исправлено

**Цель:** парсер tool-call / обрезка результата инструмента
(`truncateToolResult` в `src/answer-parse.ts`).

**Баг:** функция резала результат по фиксированному смещению символов. На
результате с эмодзи/астральной CJK-графикой разрез попадал МЕЖДУ половинами
суррогатной пары, и модель получала lone high surrogate — битый code point,
который часть каналов превращает в `?` или отбрасывает вместе с остатком

`argument-hint` — в списке «/» подсказка аргументов не показывалась.

**Фикс:**
- `truncateToolResult` при разрезе внутри суррогатной пары отступает на один
  UTF-16 юнит (пара отбрасывается целиком);
- `buildSlashCommandHints` пробрасывает `hint` динамических команд.

**Тест:** `test/tool-result-truncate.test.ts` +1 (RED до фикса —
«the kept text ends with a lone surrogate: de00»), `test/suggest-fuzzy.test.ts`
+1 (hint динамической команды доходит до списка).

**Гейты:** `npm test` 1095 тестов (1085 pass, 0 fail, 10 skip), `typecheck`,
